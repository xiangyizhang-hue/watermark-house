# FrameLab 安卓个人版 0.3.4

定位：个人使用的离线水印编辑版，不是原完整手机规划已全部完成的声明。

## 安装与使用

- 面向 ARM64、Android12及以上；vivo X100s 使用 arm64 release APK。不要安装 x86_64 模拟器包。
- 包名 `com.framelab.app`，versionCode `3004`。沿用此前0.3.3个人包签名，直接覆盖安装；不要先卸载，卸载会清除应用私有原图和记录。
- 页面和字体资源随包内置，不需要电脑、开发服务器或5180端口。
- 从图库导入照片，进入编辑后使用水印/文字/画面/信息/模板；模板库中的“保存当前配置”用于跨照片复用。
- 修改等待“已保存”提示。若显示保存失败，先处理存储问题，不要卸载或清除数据。
- 导出时保持应用前台和屏幕亮起；切后台后批量任务会暂停，回来后继续。照片保存在系统相册 FrameLab，不覆盖原片。

## 本次重点修复

1. Android离线打包、原生调用命名、原图/历史持久化。
2. 手机模板保存入口与失败反馈，保存失败不伪装成功、不覆盖现有模板。
3. 正常自动保存成功提示；只对已提交的编辑版本显示已保存。
4. 系统选图必须等原图读完再清空文件控件；空图库首张插入不再更换控件。
5. 原片INFO读取同样延迟清空控件。
6. Activity重建时不再关闭进程级数据库工作线程；媒体清理与写入串行执行。
7. 批量失败/取消恢复按实际已保存项推进，不因“尝试过全部图片”就清空队列。

## 已知边界（请先看）

- 目前是前台导出，尚未交付独立原生后台分块渲染。通知栏进度不代表能锁屏继续渲染。
- 已测24MP合成图原尺寸JPG/PNG、四张混合比例批量；尚未完成64MP/1亿像素真实照片、10～30张批量和内存峰值验证。应用不会偷偷缩小输出，但大图仍可能超出WebView能力。
- 模板保存在应用本地；手机模板JSON导入导出、完整本地备份/恢复尚未完成。不要清除应用数据。
- 未完成全Android12/14/15/16矩阵、全部触控手势/所有桌面功能逐项等价验证；不能称为完整桌面复刻。

- 沿用原先个人开发证书以兼容覆盖升级；release关闭调试，但这不是新建立的独立生产签名体系。密钥备份不要随源码分享。

## 后续维护

源码以交付快照为准。继续使用同包名/签名，版本号递增；只通过自己的安装包升级，不接原作者更新地址。桌面源码和安装包保留。

构建入口：`scripts/android-local-test.ps1 -Architecture arm64 -Variant release`。脚本记录本机JDK/SDK/NDK路径，其他电脑需按实际路径调整；`npm ci`准备前端依赖。Android构建必须使用 `custom-protocol` 和 `tauri.android.offline.conf.json`。

脚本默认离线缓存构建；首次依赖下载需联网运行Gradle，不能把缺依赖当作通过。最终验收与校验值见同目录测试报告与SHA256文件。
