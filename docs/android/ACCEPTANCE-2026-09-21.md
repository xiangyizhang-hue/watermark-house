## 系统选图阻塞（已修复并经实际包复验）

实际点开 Android Photo Picker，选图后报 `NotReadableError`（原图保存阶段），不是格式不支持。此前通过 File input 注入合成 File 的测试没有覆盖这个问题。

定位实验：保留同一个 input 的选中文件、不执行原来的立即清空语句，原图导入成功，图库由4张变5张。源代码已改为 `await addFiles` 完成后才清空，并将 input 移到稳定父节点，避免空图库导入第一张后换分支销毁该节点；导入期间禁用重复导入。

新增 `LibraryView.test.ts` 验证：异步导入中不能清空；首张插入使图库分支切换时 input 不变；导入成功后才清空。实际包多张导入、后续升级与重启恢复已完成。

下午复验：真实修复候选包经系统选图器一次选两张，图库从5张增到7张，无错误弹窗；后续升级与重启两张仍在。模拟器临时注入不是该次通过依据。INFO导入的同类过早清空也已修正。

## 字体/显示配置测试

- 375dp、系统font_scale=1.5：快捷文字自动换行，无页面横向溢出；长面板可滚动。真实键盘展开后输入区域位于键盘上方；安卓返回先收键盘，面板保留。
- 发现旧插件在Activity销毁时关闭线程，重建后出现数据库任务拒绝。已改为进程级串行线程和applicationContext，媒体清理同队列执行。
- 连续改变字体/显示尺寸还会触发Tauri多WebView恢复挂起；补齐Manifest的fontScale/density/layoutDirection配置处理，避免这类变化重建Activity。此项需以补齐后的包复验，不能仅凭线程修复计通过。
- 本轮完整自动测试：47文件、368项通过。JSDOM部分Canvas测宽用回退路径，不能当作实际像素比对结果。
